# Architecture Decision Records

Architecture Decision Records (ADRs) capture significant choices that affect
structure, security, operations, dependencies, or long-term maintainability.

## Process

1. Copy `0000-template.md` to the next sequential number.
2. Give it a short kebab-case name.
3. Record the context, decision, alternatives, and consequences.
4. Set the status to proposed.
5. Change the status after review; do not rewrite accepted history. Supersede it
   with a new ADR when a decision changes.

No architectural decision is considered accepted merely because it appears in
an unreviewed pull request.
