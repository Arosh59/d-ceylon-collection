# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in public issues, discussions, or pull
requests. Report them privately to the repository security contact designated by
the project owner. A dedicated security mailbox or private advisory channel must
be configured before the repository becomes public.

Until that channel exists, contact the project owner directly and include:

- the affected component and version or commit;
- reproduction steps or a minimal proof of concept;
- the potential impact;
- any known mitigations; and
- whether the issue has been disclosed elsewhere.

Never include real customer, traveller, authentication, payment, passport, or
private-document data in a report.

## Response expectations

The security team will acknowledge reports, assess severity, coordinate a fix,
and agree on disclosure timing with the reporter. Exact service-level objectives
will be documented before production launch.

## Supported versions

No production version exists during Phase 0. A supported-version policy will be
published with the first release.
